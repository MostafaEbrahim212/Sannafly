# Hardening & Test Suite Report

## Executive Summary
This report documents all security, financial-precision, access-control, and test-infrastructure findings verified and fixed across Phases 1–4.

---

## Phase 1: Payment & Order Flow

| ID | Issue | Status | Root Cause | Fix | Regression Tests | Residual Risk |
|---|---|---|---|---|---|---|
| 1.1 | CSRF blocks gateway callbacks | **Real & Fixed** | `bootstrap/app.php` had no `validateCsrfTokens` exclusion for `payments/callback/*`. | Added `payments/callback/*` exclusion in `bootstrap/app.php`; verified `paymentReturn` only updates state on verified gateway output. | `PaymentHardeningTest::it enforces CSRF on normal POST routes while excluding payment callbacks`, `it does not change order state on paymentReturn when callback verification fails` | None; exclusion is scoped strictly to `payments/callback/*`. |
| 1.2 | Currency hardcoded to USD | **Real & Fixed** | `OrderService::placeOrder` hardcoded `'currency' => 'USD'` and `SettingsSeeder` defaulted to `USD`/`$`. | Read `currency` from `SettingsService` (default `EGP`), updated `SettingsSeeder` to `EGP`/`ج.م`, rejected non-EGP in `FawryGateway::initiate`, validated ISO currency in `MyFatoorahGateway::initiate`. | `PaymentHardeningTest::it creates orders with currency from settings (default EGP) and snapshots it against later changes`, `it refuses to initiate Fawry payment when order currency is not EGP` | Admin changing currency mid-session only affects new orders. |
| 1.3 | Paid amount/currency not verified on callback | **Real & Fixed** | `applyPaymentOutcome` marked orders `paid` without checking gateway `amount` or `currency`, and didn't guard out-of-order callbacks. | Extended `verifyCallback` with `amount` and `currency`; compared via `bccomp` (scale 2); flagged mismatches as `amount_mismatch` + audit log; ignored `failed` after `completed`; flagged `completed` after `cancelled` as `needs_review`. | `PaymentHardeningTest::it rejects underpaid Fawry callback...`, `it rejects overpaid Fawry callback...`, `it rejects MyFatoorah callback with wrong currency...`, `it does not cancel a paid order when a late failed callback arrives`, `it does not silently confirm a cancelled order when a late completed callback arrives` | Mismatched/late-paid callbacks return HTTP 200 (`flagged_for_review`) to prevent gateway webhook retry storms; ops must monitor `amount_mismatch` / `needs_review` orders. |
| 1.4 | Unpaid orders hold stock forever | **Real & Fixed** | No scheduled job existed to expire abandoned unpaid orders. | Added `orders:expire-unpaid` command with configurable TTL settings (`unpaid_online_ttl_minutes=60`, `unpaid_bank_transfer_ttl_minutes=1440`, `unpaid_cod_ttl_minutes=0`) and 5-min schedule in `routes/console.php` using `lockForUpdate()`. | `PaymentHardeningTest::it expires only eligible unpaid online orders and releases stock exactly once` | Requires `php artisan schedule:run` cron in production. |
| 1.5 | Cancel/refund correctness | **Real & Fixed** | Cancelling did not release coupon `used_count`, left paid online orders as `payment_status=paid`, and allowed `shipped -> cancelled`. | Added `releaseCoupon()`, `refund_pending` state + `PaymentGatewayInterface::refund()` behind `auto_refund` flag, and removed `cancelled` from `ALLOWED_TRANSITIONS['shipped']` (ADR-001). | `PaymentHardeningTest::it releases coupon used_count...`, `it marks paid online order as refund_pending...`, `it forbids cancelling an order once it has been shipped` | Gateway auto-refund requires `auto_refund=true` in gateway config; otherwise manual refund is required. |
| 1.6 | Idempotency race & cross-actor replay | **Real & Fixed** | `idempotency_key` was global (not actor-scoped) and didn't catch `UniqueConstraintViolationException`. | Scoped keys via SHA-256 of `actor_scope|key` (ADR-002), caught `UniqueConstraintViolationException` and re-fetched existing order, and stored server-generated key in session. | `PaymentHardeningTest::it scopes idempotency keys to the actor...`, `it handles UniqueConstraintViolationException on idempotency_key race...`, `it generates server-side idempotency key in session...` | None. |
| 1.7 | Floating-point money math | **Real & Fixed** | `OrderService`, `Coupon`, `ShippingZone`, `ShippingService`, and `CartCheckoutController` used `(float)` and `round()`. | Introduced `App\Support\Money` (BCMath with half-up rounding at 4 decimals internally, 2 for gateway) and replaced float math across all order/coupon/shipping/gateway calculations. | `MoneyPrecisionTest` + `tests/Unit/MoneyTest.php` | Frontend display formatting still formats numbers in JS for UI presentation only; authoritative totals are computed server-side. |

## Decisions for Review
1. **ADR-001 (`shipped -> cancelled`):** Disallowed cancelling shipped orders; must use `returned` -> `refunded` to protect inventory accuracy.
2. **ADR-002 (Idempotency Scoping):** Scoped to `customer:{id}` or `session:{id}` rather than global keys.
3. **ADR-003 (Order Number Format):** Increased random suffix from 6 to 10 CSPRNG characters.
4. **ADR-004 (CSP Rollout):** Enabled `Content-Security-Policy-Report-Only` by default via `config/security.php`.
5. **Callback Mismatch HTTP Status:** Returns `200` (`flagged_for_review`) after persisting `amount_mismatch` / `needs_review` and auditing, so gateways do not infinitely retry terminal mismatches.
